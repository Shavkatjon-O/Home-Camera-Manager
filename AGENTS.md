# Home cameras

## Commands

Run the stack from the repository root:

```
docker compose up -d --build
docker compose logs -f backend
docker compose down
```

The host has no Node or project Python environment; run tools in containers as your own user.

```
docker run --rm -u $(id -u):$(id -g) -e HOME=/tmp -e UV_PROJECT_ENVIRONMENT=/tmp/venv -e UV_CACHE_DIR=/tmp/uv-cache -v $PWD/backend:/work -w /work ghcr.io/astral-sh/uv:python3.13-bookworm-slim sh -c "uv sync --frozen && uv run --frozen ruff check . && uv run --frozen ruff format --check . && uv run --frozen pytest -q"

docker run --rm -u $(id -u):$(id -g) -e HOME=/tmp -e COREPACK_HOME=/tmp/corepack -e PATH=/tmp/bin:/usr/local/bin:/usr/bin:/bin -v $PWD/frontend:/app -w /app node:24 sh -c "mkdir -p /tmp/bin && corepack enable --install-directory /tmp/bin && pnpm install --frozen-lockfile && pnpm lint && pnpm typecheck && pnpm build"
```

Create a migration from backend/ against a database already at head, with the stack's postgres or a temporary one on the same network:

```
alembic upgrade head
alembic revision --autogenerate -m "<message>"
```

## Rules

- The backend follows the canonical FastAPI module layout: routers call services, services own the transaction, models register in app/models/__init__.py, because Alembic and the import order depend on that registry.
- Never hand-write or edit a migration; commit the autogenerated file as written, because a wrong migration loses the registry.
- Keep go2rtc.yaml free of streams and mounted read-only, because go2rtc writes stream URLs with camera passwords into its config when it can.
- Keep the player asking for H.264 only, because go2rtc's direct H.265 path from the V380 delivers no frames.
- Keep rtsp.listen on loopback inside go2rtc, because every ffmpeg transcode source reads the stream back through go2rtc's RTSP server.
- Proxy the video websocket with the browser's Host header, because go2rtc rejects websocket origins that do not match it.
- Keep transcodes video only, because bridged V380 cameras advertise an audio track they never send and an audio transcode then waits until go2rtc kills it.
- Keep the go2rtc h264 template on h264_nvenc with CPU decoding, because software x264 on the 5 MP streams misses go2rtc's start timeout and GPU decoding fails on the PTZ 1 bridge stream.
- Build the V380 bridge from the pinned upstream pull request commit in v380-bridge/Dockerfile, because the released decoder stalls on short stream login replies and the camera resets the connection.
- Never publish bridge ports, because their RTSP and ONVIF have no authentication.
- No comments, emojis or non-ASCII characters in code, configs or docs.
